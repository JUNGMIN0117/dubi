# v12 참조 변환 캐시 수정 및 로컬 회귀 검증

상태: 로컬 수정·검증 완료 / 운영 미배포. 전달받은
`docs/ml-serving-latency-analysis.md`는 원격 develop(a077adf), master(86f9ae1)에
없었다. 이 문서는 그 측정 보고서를 대신하거나 운영 3.7초 측정을 재현한 결과가 아니다.

## 수정 범위

`ml-serving/reference_cache.py`의 portable 모듈 전용 읽기 어댑터에서 pandas
변환 결과를 LRU로 재사용한다. pandas 직접 읽기와
`ParquetFile.read(columns=...).to_pandas()` 두 형태가 대상이다.
요청에는 깊은 복사본을 반환해 ID·수치 스칼라 열의 수정을 격리한다.
중첩 가변 객체가 들어가는 새 참조 스키마는 별도 검증이 필요하다.
모델, portable 파일, 참조 파일, SHA 목록과 시작 시 검증 규칙은 변경하지 않는다.
공개 HTTP 계약과 production_ready 상태도 바꾸지 않는다.

Arrow와 pandas가 같은 메모리 예산을 사용한다. pandas는 인덱스·문자열을 포함한
memory_usage(deep=True)를 기준으로 한다. 한도를 넘는 단일 표는 저장하지 않는다.
파일 오류와 미검증 경로는 기존처럼 실패한다. 캐시는 Predictor 단일 추론 락 안에서
사용하며, 전체 RSS·복사본·변환 임시 메모리를 제한하는 기능은 아니다.

## 검증

- ML 전체 테스트: 65개 통과. 원본 v12 실제 golden 결과와 캐시 없는 reader 비교 포함.
- 신규 회귀: 두 읽기 형태의 재사용, 요청 간 수정 격리, pandas 추정 크기,
  Arrow/pandas 공용 예산, LRU 제거, 상한 초과 및 비활성 동작.
- 최신 설치 묶음 `artifacts/ml-serving/20260908-v12-ref-20260917-through-1010-r2`:
  `examples/v12-server-golden.json`의 10개 입력에 service_date=2026-09-18을 적용했다.
  cold/warm/원본 reader의 results 전체(예측값·결측·상태·순서)가 일치했다.
- 최신 develop 병합 후 Backend 로컬 테스트: 364 통과, 기존 조건부 생략 4개.
  Docker가 없어 DB 통합 테스트는 이번 병합 상태에서 로컬 실행하지 않았다.

## 로컬 관찰값과 한계

| 캐시 상한 | 첫 요청 | 반복 요청 1 / 2 | 보관 추정 크기 | 반복 요청의 추가 miss |
|---|---:|---:|---:|---:|
| 256MiB | 1.958초 | 1.722 / 1.635초 | 184,153,346 bytes | 매번 1 |
| 512MiB | 1.926초 | 1.565 / 1.541초 | 455,512,587 bytes | 0 |

256MiB 실행에서 원본 reader로 복원한 요청은 1.827초였다.
512MiB의 3회 요청 결과도 서로 일치했다. 적은 횟수의 개발 PC 측정이며
서버의 p50/p95 또는 개선율 보장으로 해석하면 안 된다.
기본 256MiB에서는 큰 표가 271,359,241 bytes라 상한을 넘어 다시 변환된다.
512MiB에서는 16개 표가 모두 보관되지만 서버 메모리 여유를 확인하지 않았으므로
기본 설정을 올리지 않았다. 운영 3.1초 준비 시간의 해소 여부는 미확인이다.
