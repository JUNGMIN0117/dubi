## 프로젝트 공부 정리
- 뚜비는 일정과 실시간 교통·사고·행사 정보를 결합해 권장 출발 시간과 이동 경로를 알려주는 서비스다.
- 외부 길찾기 API가 이동 가능한 후보 경로를 만들고, 뚜비는 지연·위험·일정 중요도를 반영해 후보의 순위를 다시 정한다.
- 전체 흐름은 외부 데이터 수집 → Kafka 전달 → Spark 분석 → Redis 최신 결과 저장 → Spring Boot 추천 계산 → Flutter 화면·알림 제공 순서로 구성된다.
- MySQL은 회원·일정·추천·구간 매핑처럼 정확한 관계가 필요한 데이터를 저장하고, Redis는 빠르게 조회할 최신 상태를 저장한다. 경로 후보 생성은 외부 API가 맡으므로 PostGIS 기반 공간 네트워크 탐색은 MVP 핵심이 아니며, 행사·사고 영향은 `segment_id`로 연결하는 방향이 더 단순하다.
- Kafka는 데이터를 전달하고 잠시 보관하는 역할이며, HDFS는 원본과 과거 이력을 저장해 같은 상황을 다시 Replay하는 데 사용한다.
- 지오코딩은 주소나 장소를 위도·경도 좌표로 변환해 지도, 교통 데이터와 연결하는 과정이다.
- ERD를 작성할 때는 화면의 입력값만 보는 것이 아니라 회원·일정·장소·경로·추천 결과 사이의 관계와 저장 책임을 함께 고려해야 한다.
- 현재는 규칙과 통계 기반 기준선을 먼저 만들고, 실제 데이터가 쌓인 뒤 예측 모델의 필요성과 성능을 검증하는 것이 적절하다.
